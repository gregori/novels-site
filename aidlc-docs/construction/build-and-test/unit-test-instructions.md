# Unit Test Execution

## Run Unit Tests

### 1. Execute All Unit Tests
```bash
npm test
```
Runs `vitest run` once (non-watch). Use `npm run test:watch` during development for watch mode.

### 2. Review Test Results
- **Expected**: 5 test files, 16 tests, 0 failures
- **Test Coverage**: no coverage threshold is enforced (small static-site codebase, testing targeted at pure functions per the Property-Based Testing extension scope, not exhaustive coverage)
- **Test Report Location**: console output only (no HTML/JSON report is generated by default)

### Test Suite Contents (`tests/unit/`)
| File | Covers |
|---|---|
| `theme.test.ts` | `resolveInitialTheme` — stored theme preference vs. OS preference fallback (BR-7) |
| `typography.test.ts` | Typography preference resolution — default and stored/invalid fallback (BR-7) |
| `search.test.ts` | `searchTitles` — empty/whitespace query handling (BR-6) |
| `categories.test.ts` | `normalizeCategory` and `deriveCategories` — case/whitespace-insensitive grouping (BR-2) |
| `chapters.test.ts` | `getRecentChapters`, `getChaptersForTitle` — ascending sort by filename (BR-3) |

Property-based tests (fast-check) are included where the NFR requirements scope them: pure functions and serialization round-trips (per PBT-09).

### 3. Fix Failing Tests
If tests fail:
1. Read the Vitest failure output (file, assertion, expected vs. actual)
2. Reproduce the specific failing case in isolation
3. Fix the source function in `src/lib/` (tests are colocated by concern in `tests/unit/`)
4. Rerun `npm test` until all pass
